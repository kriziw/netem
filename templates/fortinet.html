1. Prepare API access on the FortiGate

NetEm needs a REST API token before it can discover or configure the appliance. Complete these steps in the FortiGate GUI, using an account with the super_admin profile. The default login username is admin; root is the default VDOM, not a username.

  1. Confirm management access. Open the FortiGate management HTTPS address in another browser tab. Keep this management port separate from LAN and WAN test ports, and keep console access and a configuration backup available. The FortiGate management interface must allow HTTPS and be reachable from the NetEm host.
  2. Create an API administrator profile. In System → Admin Profiles, create a profile such as netem-lab-api. Give System: Read, Network: Read/Write (interfaces, routing and SD-WAN), and Firewall: Read/Write (addresses and policies). Leave unrelated categories at None. Select the lab VDOM where applicable. These permissions cover this wizard; a read-only monitoring profile cannot push the base configuration. Permissions and global-interface visibility can vary with firmware/VDOM mode; a denied discovery identifies an account-access problem.
  3. Create the REST API administrator. Go to System → Administrators → Create New → REST API Admin. Use a dedicated name such as netem-lab, select the profile above and the lab VDOM (usually root). Restrict Trusted Hosts to the NetEm host's management/source IP as seen by the FortiGate, normally a single-host /32. This is the NetEm server's address, not your browser's address. If NAT sits between them, use its translated source. NetEm makes server-side requests, so browser CORS access is not required. Leave PKI/client-certificate authentication unset; this integration uses the API token.
  4. Save and copy the token. Click OK and copy the generated API token while it is shown. FortiGate shows it only once. Paste it into Step 2 below; do not paste the admin password. If the token is lost, generate a replacement for that API administrator and update NetEm. A CLI administrator can regenerate it with execute api-user generate-key netem-lab.

2. Save the FortiGate connection in NetEm

The token authenticates the API user created in Step 1. NetEm does not need a login username or password.

Use the management address and optional HTTPS port. Do not add an API path.

Usually root. This must be a VDOM allowed for the API administrator.

Paste the token generated in Step 1.

For a certificate signed by a trusted CA, leave this unchecked. For a self-signed certificate, obtain its SHA-256 fingerprint through a trusted management connection or exported certificate and verify it independently before saving.

For an exported PEM certificate: openssl x509 -in fortigate-management.pem -noout -fingerprint -sha256. Paste the fingerprint after the equals sign. Required for self-signed trust; a changed certificate must be reverified.
