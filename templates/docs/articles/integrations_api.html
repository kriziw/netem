Vendor-neutral integration model

The core API describes injected state, measured traffic, active measurements, session context and events without depending on any SD-WAN vendor. Future vendor adapters add an observed-state layer rather than changing the impairment engine.

GET /api/v1/state

Returns application version, WAN definitions/effective impairment, expected SLA, scenario state, active Lab Session, packet capture and configured probes with their latest results.

curl -s http://NETEM:8081/api/v1/state | python3 -m json.tool

GET /api/v1/telemetry

Returns cumulative raw Linux interface counters plus normalized directional download/upload counters. This is the lowest-level live telemetry endpoint.

GET /api/v1/history

Returns server-side SQLite time-series history for one WAN. Required link_id; optional minutes and max_points are bounded by the backend. Longer time ranges are bucket-aggregated to keep responses bounded.

curl -s "http://NETEM:8081/api/v1/history?link_id=wan1&minutes=60"

The response includes persisted WAN samples and probe samples in the selected interval.

GET /api/v1/probes

Returns all configured active measurements and their most recent result.

curl -s http://NETEM:8081/api/v1/probes

GET /api/v1/events

Returns recent runtime events. Assertion and probe transition events contain structured details suitable for automation.

Session report JSON

GET /sessions/<session-id>/report.json returns the completed evidence report: result, assertions, test runs, WAN statistics, probe statistics and correlated events.

GET /metrics

Prometheus remains an optional external export surface and is not required for the internal SQLite telemetry/history functions.

Future vendor adapter contract

The next integration milestone is a normalized adapter output containing member health, observed latency/jitter/loss, SLA state, selected path and transition timestamps. Fortinet is the recommended first adapter, followed by Cisco, Palo Alto, Juniper, VMware/VeloCloud and Versa.

NetEm injected state ─┐ Active measurements ──┼─→ Session / Analytics correlation Vendor adapter state ─┘

API guidance

Use /api/v1/state for current normalized state, /api/v1/history for rate/time-series history, /api/v1/probes for independent measurement state and session-report JSON for completed validation evidence.
