Vendor-neutral integration model

The core API describes what NetEm is doing without depending on Fortinet, Cisco, Palo Alto or another vendor. External tools can consume that state directly, and future vendor adapters can normalize appliance telemetry into a common model.

GET /api/v1/state

This is the primary high-level state endpoint. It returns application version, WAN definitions, runtime-effective impairment, configured quality, current fault, MTU, expected SLA, scenario state, capture state and recent events.

curl -s http://NETEM:8081/api/v1/state | python3 -m json.tool

Important WAN fields include:

FieldMeaning
idStable WAN identifier such as wan1.
preset / preset_nameSelected access technology.
configured_qualityPersisted quality slider value.
qualityCurrent runtime-effective quality, including scenario stages.
modeCurrent quality/custom runtime mode.
effectiveDelay, jitter, loss, rate and advanced impairment values in effect.
faultCurrent runtime fault state.
slaExpected pass/fail result and individual checks.
mtuCurrent inner/outer/bridge MTU values.

GET /api/v1/telemetry

This endpoint exposes cumulative Linux interface counters. Consumers calculate rates by taking deltas over time.

curl -s http://NETEM:8081/api/v1/telemetry | python3 -m json.tool

Each WAN contains both raw inner/outer counters and a preferred directional traffic view:

  • traffic.download — inner-interface TX bytes/packets toward the appliance.
  • traffic.upload — outer-interface TX bytes/packets toward the upstream router.
Counters are cumulative. A single response does not contain Mbit/s. Sample twice and divide the byte delta by elapsed time, or use the built-in live UI.

GET /api/v1/events

Returns persistent runtime events. The optional limit query parameter is bounded to 1–500.

curl -s "http://NETEM:8081/api/v1/events?limit=50"

Event objects contain a Unix timestamp, event kind, human-readable message and structured details.

GET /metrics

The Prometheus endpoint exports configured quality, runtime-fault state and raw RX/TX byte counters for each inner/outer interface. It is intended for external monitoring and long-term retention; Prometheus is not required for NetEm itself.

curl -s http://NETEM:8081/metrics

History downloads

  • GET /lab/history.json — JSON export of retained events.
  • GET /lab/history.csv — CSV export suitable for spreadsheets or analysis tools.

Safe security endpoints

  • GET /lab/security/eicar.txt — harmless EICAR test artifact.
  • GET|POST /lab/security/beacon — benign callback sink returning HTTP 204.

Future vendor adapters

The intended adapter output is a common model containing member health, observed latency/jitter/loss, SLA state and selected path. A Fortinet adapter and a Cisco adapter should therefore feed the same UI model rather than creating vendor-specific dashboard pages.

vendor API / manager │ ▼ optional adapter │ ▼ normalized member model │ ├── health ├── latency / jitter / loss ├── SLA state └── selected path │ ▼ Analytics: injected vs observed

API use guidance

Prefer the normalized high-level fields in /api/v1/state and directional traffic object in /api/v1/telemetry. Raw counters and Linux interface names remain useful for diagnostics but are more tightly coupled to the underlying topology.
