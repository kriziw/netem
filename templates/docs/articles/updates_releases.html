Stable update channel

The in-app updater always compares the installed checkout with origin/main. It does this regardless of the local branch name. This prevents older installations from becoming stranded when an old feature branch is merged and deleted.

Check stable channel

Check stable channel performs a Git fetch of origin main, refreshes the remote version and recalculates ahead/behind state.

Install update

Updates are fast-forward only. The updater refuses to install when:

  • tracked application files are modified;
  • the local checkout and origin/main have diverged;
  • the stable remote branch cannot be found;
  • Git fetch/merge fails.

On success, NetEm performs git merge --ff-only origin/main, then exits intentionally. A correctly configured systemd unit with Restart=on-failure starts the updated application again.

While this happens, a progress screen steps through Installing update, Restarting NetEm and Reconnecting, then reloads the page on the new version. It knows the restart has finished when a new NetEm process answers, so it also works when an update does not change the version number. If the update is refused, for example because of local changes, the screen says why and nothing restarts. If NetEm takes more than two minutes to come back, it suggests checking journalctl -u netem -n 50 on the appliance.

Repository ownership

The service runs as techkarma, so that user must be able to write the repository when the in-app updater fetches and fast-forwards. If manual Git commands are run as root, root-owned objects can be created under .git/objects and later block the service user.

Preferred manual Git pattern:

runuser -u techkarma -- git -C /opt/techkarma-netem status
runuser -u techkarma -- git -C /opt/techkarma-netem fetch --prune origin

If ownership has already become inconsistent:

systemctl stop techkarma-netem
chown -R techkarma:techkarma /opt/techkarma-netem
runuser -u techkarma -- git -C /opt/techkarma-netem status
runuser -u techkarma -- git -C /opt/techkarma-netem fetch --prune origin
systemctl start techkarma-netem
Design principle: system administration can be done as root, but repository/application-file operations should be performed as the service owner.

Release Please

The repository uses Release Please to manage semantic versions and release changelog PRs. The version source is version.txt; release configuration lives in release-please-config.json and .release-please-manifest.json.

Commit conventionTypical release effect
fix:Patch release
feat:Minor release
Breaking changeMajor release
docs:, chore:, etc.Included in changelog policy as configured; does not normally imply a feature bump by itself

After qualifying changes reach main, Release Please prepares/updates a release PR. Merging that release PR updates the version/changelog and creates the corresponding tag/GitHub release.

Testing an unmerged feature branch

The in-app updater intentionally follows main, so it will not install an unmerged feature branch. For a one-time preview, stop the service and switch branches manually as techkarma, then restart the service. Return to main when testing is complete.
