Injected, measured and observed data

Analytics deliberately separates three perspectives so the UI does not confuse configuration with evidence.

PerspectiveCurrent sourceMeaning
InjectedNetEm runtime stateDelay, jitter, loss, quality and bandwidth that NetEm intends to apply.
MeasuredLinux counters + active probesTraffic actually crossing the interfaces and independent ICMP/TCP/HTTP/DNS response timing.
ObservedFuture vendor adapterThe SD-WAN/firewall's own SLA health, measured metrics and selected path.

Persistent SQLite telemetry

A background worker samples each configured WAN approximately every two seconds and stores server-side time series in runtime/telemetry.db. The default retention window is 168 hours (7 days). Browser reloads therefore no longer erase historical WAN charts.

Stored WAN samples include downstream/upstream Mbit/s, downstream/upstream PPS, injected latency/jitter/loss/quality, expected SLA state, runtime fault and active Lab Session ID.

Historical range

Use the range selector beside the WAN selector to load 15 minutes, 1 hour, 6 hours, 24 hours or 7 days. The history API aggregates older ranges into a bounded number of chart points, then the browser appends fresh live samples.

Throughput and packet rate

Directional rates are derived from successive Linux counter samples:

rate (Mbit/s) = (new byte counter − previous byte counter) × 8 ÷ elapsed seconds ÷ 1,000,000

Downstream uses inner-interface TX and upstream uses outer-interface TX. Packet rate uses the equivalent packet-counter delta.

Active measurements

Analytics can continuously run four bounded probe types and persist every result to SQLite:

TypeWhat is measured
ICMPEcho reachability and reply time.
TCPConnection establishment time to a host/port.
HTTP/HTTPSTime to establish the connection/TLS session and receive an HTTP status line.
DNSUDP A-query response time via the configured resolver.

Probe intervals are limited to 2–3600 seconds and timeouts to 0.2–10 seconds. Up to 20 probes can be configured.

Transparent-path limitation: the WAN bridge ports normally carry no L3 address. A probe using Automatic source follows the NetEm host's routing table and is associated with the WAN for correlation, but it does not prove the selected transparent path was crossed. Inner/outer binding is available when that interface has a usable L3 route/source address. True appliance-side path probes require a remote probe agent or vendor observation, which remains a future extension.

Probe state transitions

Every probe sample is stored, but the event timeline is not flooded with routine successes. A probe runtime event is written only when the probe changes between success and failure/recovery.

Generic expected SLA

The generic SLA evaluator remains based on injected conditions, independent of active probes. The default thresholds are 100 ms latency, 30 ms jitter and 2% loss. Any runtime blackhole also fails the data-plane check.

Injected vs measured vs observed

The comparison table now shows NetEm's injected state beside the most recent active measurement for the selected WAN. A future vendor adapter adds the third column without changing the impairment engine.

Session correlation

When a Lab Session is active, both telemetry rows and probe samples are written with that session ID. The completed session report can therefore summarize peak throughput, worst injected conditions, SLA-fail samples, probe success rate and average/P95/max measured response time.

Historical API

GET /api/v1/history?link_id=wan1&minutes=60 returns aggregated persisted WAN samples plus probe samples for the requested period. GET /api/v1/probes returns probe configuration and the latest result for each probe.
