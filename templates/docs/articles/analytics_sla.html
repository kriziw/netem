Measured traffic vs injected conditions

Analytics intentionally combines two different types of data. Understanding the distinction is essential when interpreting the graphs.

Live analysis target

Select the WAN at the top of Analytics. The four chart panels then use that WAN's browser-side rolling history. Switching target changes the visible series without changing the WAN configuration.

Throughput chart

Downstream and upstream rates are calculated from differences between successive counter samples:

rate (Mbit/s) = (new byte counter − previous byte counter) × 8 ÷ elapsed seconds ÷ 1,000,000

Directional mapping is explicit: downstream uses the inner interface TX counter and upstream uses the outer interface TX counter. Both series share the same dynamic Y-axis scale so their visual relationship is meaningful.

Packet-rate chart

Packet rate uses the equivalent packet-counter delta and is shown as downstream/upstream packets per second. It can reveal behavior that bandwidth alone hides—for example, a high PPS stream of small packets.

Latency, jitter, loss and quality

Latency and jitter share one dynamic millisecond scale. Loss and quality share a fixed 0–100% scale. These graphs show NetEm's current injected state, including temporary scenario stages, because the runtime state API tracks the effective profile actually applied.

Sampling and time window

The UI polls approximately every 1.5 seconds. Analytics stores up to 200 samples per WAN in the current browser page, giving roughly a five-minute rolling view at that sampling interval. Reloading the page resets this chart history. The event log is persistent; the chart time series is not yet stored server-side.

Generic SLA evaluator

The SLA profile defines maximum accepted latency, jitter and packet loss. The default profile is:

MetricDefault threshold
Latency100 ms
Jitter30 ms
Packet loss2%

The expected SLA passes only when all three metrics are within threshold and no runtime data-plane fault is active. A blackhole therefore fails the data_plane check even if the saved latency/jitter/loss values are otherwise healthy.

Edit the SLA profile

  1. Open Analytics.
  2. Scroll to Generic SLA evaluator.
  3. Give the profile a descriptive name.
  4. Set maximum latency, jitter and loss.
  5. Click Save SLA profile.

The profile is persisted in config.json and immediately affects expected PASS/FAIL status across Overview, WAN Links, Analytics and the state API.

Injected vs observed

The current Injected vs observed table only has the NetEm side populated. The observed column is reserved for future SD-WAN/firewall adapters. The intended model is:

NetEm injected state Appliance observed state 80 ms latency 84 ms SLA latency 3.0% loss 3.2% SLA loss expected SLA FAIL appliance SLA FAIL selected path = WAN2

With that data, future scenario reports can calculate detection delay, failover delay and recovery convergence rather than only displaying impairment values.

Event timeline and export

Analytics shows recent persistent events newest first. Use the JSON or CSV buttons to export up to the retained event-history window. Events are operational records, not packet-level telemetry.
