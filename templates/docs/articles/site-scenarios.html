Choose the client site

Open Tests → Site scenario. Select the industry, sub-industry, site function, size and criticality separately. For example: Manufacturing → Automotive → Manufacturing plant → Large → Mission-critical.

The preview derives employees, concurrent staff and devices, persona shares, application emphasis, experience targets, typical primary/backup WAN lines and an ordered test plan. These are lab assumptions, not a capacity survey or production SLA. Adjust the simulated user count before running. Counts above 5,000 are capped while retaining the persona proportions.

Activate targets and WAN lines

Save as active site activates the site badge and experience targets in the Command Center. Check the explicit SLA replacement option only if you also want to replace the current model WAN SLA thresholds. Saving a profile does not change WAN lines.

Choose two different WANs as primary and backup, then use Apply WAN lines to replace their saved presets and bandwidth limits with the suggested lines. For a large mission-critical plant the suggestion is DIA 1,000/1,000 Mbit/s plus a diverse DIA 500/500 Mbit/s backup. Carrier diversity must be provided by your actual lab topology.

Active site indicators are green when the target is met and red when missed; absent measurements are gray. Interactive P95 excludes large transfers. Steering reaction is measured using a rolling ten-second traffic window, so assertions allow an additional ten seconds to observe the result, while still judging the reported reaction against the chosen target.

Mission-critical sites use strict voice/video judging. Safety-sensitive sub-industries also use strict judging at lower criticality. OT telemetry remains intolerant of loss in either media mode.

Run and stop

Run an individual test or Run all. The plan includes baseline, primary brownout and primary outage; business-critical sites add backup outage and primary congestion; mission-critical sites add intermittent primary failures. Congestion is approximated by reducing primary quality to 30%, which also changes delay and loss; it is not a pure bandwidth saturation test.

Tests start and stop their own site workload, record assertions and per-test results in the activity log, and restore the tested WAN to its saved configuration. Stop plan & restore stops the current test and skips remaining tests. A failed assertion marks that test failed; later tests still run. Start a lab session before running to retain evidence in its report.

Simulator and lab requirements

Connect the Traffic Simulator under Settings → Integrations. Industry applications and personas require the simulator’s industry-app update. Older catalogs remove unsupported applications/personas and show a warning; their reduced workload is not equivalent to the full industry simulation. Per-WAN steering also requires an updated target and appliance egress addresses mapped to the WANs.

Before evaluating a customer appliance, validate both paths and the baseline. The site catalog does not configure appliance SD-WAN policies. Generic and custom tests remain available below the site selector.
