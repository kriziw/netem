What the showroom is for

The showroom is a read-only live dashboard for a demo screen or a customer-facing display. It answers three questions without operator controls:

  1. Who is this site? The client industry and sub-industry, site function, size and criticality, its people and devices, the experience targets and typical WAN lines, and the running lab session.
  2. What is happening on the network? The test that is running, its phases and the time to the next phase, the simulated workload and application mix, and the measured traffic on every WAN.
  3. What do users get? Experience, request success and interactive response against the targets, where a problem happens and why, whether the SD-WAN appliance steers traffic away from an impaired WAN, and a report once a test ends.

Open it

The showroom listens on its own port, 8082 by default, on every address of the appliance. Settings shows the address to open. Show it full screen in a browser on the display; it fits a 1080p screen without scrolling and scales up to 4K.

Two environment variables change the listener (add Environment=... lines to the systemd service):

  • NETEM_SHOWROOM_PORT=8082: another port; 0 disables the showroom. It cannot use the operator port 8081.
  • NETEM_SHOWROOM_HOST=0.0.0.0: bind to one address only, such as a showroom-facing interface.

Allow the port through the appliance firewall for the showroom network only.

MSP and SD-WAN vendor

The header shows the MSP brand chosen in Settings → Branding and, next to it, the SD-WAN vendor and model under test, so clients see at once who runs the lab and which appliance they are watching.

Waiting screen

With no lab session, no test or site test plan running and no recent report, the showroom shows a calm waiting screen: the MSP brand and the SD-WAN vendor in the header, "Waiting for the session to start" and, when a site is selected, the client site. The live dashboard appears as soon as the operator starts a session or a test.

Coming up

For 5 seconds before each test starts, the screen shows what is coming: the test and its WAN, a short description, each phase with its length and what it does (for example "Primary blackholed"), the checks it makes, and a countdown. In a site test plan this happens before every test, with the test's place in the plan. Then the live dashboard returns and the test begins. The screen checks for news every second while no test runs, so the announcement appears within a second.

Client site band

The band at the top shows the site of the running lab session. Without a session it shows the active site profile from Tests → Site scenario. Choose the site when starting a session so the screen and the session report name the same client. With no site at all, the screen says so and judges results against the Command Center's lab thresholds.

Network & activity

  • Running now: the test name, the WAN it runs on, the current phase and step, the phase timeline and elapsed time against the planned length, and when the next phase starts. When the operator pauses a test, the panel turns amber and the countdown waits until the test resumes. A site test plan shows which test of the plan is running.
  • Simulated users: users currently running in the Traffic Simulator, the activity level and the voice/video judging mode.
  • WAN cards: the WAN's health in a word (Healthy, Busy, Degraded, Down), what NetEm is doing to it in plain words (for example "Impaired to 60% quality: 45 ms delay, 2% loss" or "Outage injected"), measured download and upload averaged over about 10 seconds, a two-minute traffic chart, and which kinds of traffic the appliance sends over it. With more WANs than fit the screen, the cards rotate every 12 seconds.

Experience outcome

  • Result tiles: experience score, request success and response time (P95) over the last minute, green when the site target is met and red when missed.
  • What's happening: one sentence about users, the WANs and the appliance's latest move, for example "Users are affected. WAN1 is degraded. The appliance moved voice and video off WAN1 in 12 s." Below it are up to three user impacts, each with its cause in plain words, for example "Voice and video: breaking up", caused by "2% packet loss on WAN1". An impact shows once it has lasted about 8 seconds and stays for 30 seconds after it ends, marked resolved. Transfers that are only limited by the line speed are left out.
  • Where the appliance sends traffic: for voice and video, web and business apps, and file transfers, the WAN that carries most of it, with a tick when that WAN is healthy and a warning when it is not.

Health, routes and the target verdicts change on screen only after a change has lasted about 8 seconds, so the screen reads calmly from across a room. An outage shows at once. The Command Center keeps the detailed, second-by-second diagnosis for operators.

Test report

When a test ends, its report replaces the live findings for 30 minutes, or until the next test starts. The report shows:

  • the result, the WAN, the site, the duration and how many checks passed;
  • a short conclusion, for example how far experience fell and in which phase;
  • one row per phase with experience, request success (and its lowest point), interactive P95, average traffic per WAN and the steering verdict per traffic class;
  • SD-WAN remediation: which traffic the appliance moved, from which WAN, how fast, and whether that met the site's steering target.

The same summary appears on the Tests page and, for tests run in a lab session, in the session report.

Run sequence results

When a site test plan with Run all finishes, or is stopped, its results fill the screen for 30 minutes, until the next test starts or a new session begins:

  • the verdict, for example "4 of 5 tests passed", the result, the total time and how many checks were met;
  • one row per test: its result, WAN and checks, experience at baseline and its lowest point with the phase, the lowest request success, the slowest interactive response, and which traffic the appliance moved and how fast;
  • what the run showed, up to seven sentences led by what needs attention: failover slower than the target, traffic left on an impaired WAN, missed checks, the lowest experience, then baseline experience, failover within the target and the tests users did not notice.

The same verdict and sentences appear under the plan on the Tests page.

What it publishes

The showroom is a separate web application with only the dashboard, its two assets and a presentation snapshot. It never publishes configuration, secrets, interface names or addresses; addresses in diagnosis texts are replaced with "[address]". It accepts only GET and HEAD and has no controls, so pausing or stopping a test is done from the operator interface. The showroom has no login: anyone who can reach its port can watch it.

Connection loss

The page polls every two seconds during a test and every second otherwise. If the appliance stops answering, the badge shows Connection lost, live rates are blanked, the last known state is labelled as such, and charts show a gap instead of zero traffic. It reconnects on its own.

Branding

The showroom uses the appliance brand: name, logo, favicon, font and colours. See Appliance branding.
