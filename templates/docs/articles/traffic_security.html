Safety model

Traffic & Security is designed for controlled lab validation, not unrestricted attack generation. Current security functions either produce harmless test artifacts, receive benign callbacks, simulate availability impact through WAN impairment, or capture packets on configured lab interfaces.

EICAR anti-malware test

Download EICAR artifact serves the standard EICAR antivirus test string as a text attachment. It is not malware and does not execute code. Use it to verify whether an inline security control, endpoint product or policy detects the standard test signature.

Requesting the artifact writes a security-test event to the NetEm history.

Benign beacon sink

The beacon endpoint accepts HTTP GET or POST callbacks and returns HTTP 204 with no command or executable content. It records the request method and a bounded user-agent string in event history.

Typical use:

  1. Copy the endpoint shown in Traffic & Security.
  2. From a controlled lab client, make periodic GET/POST requests to that URL.
  3. Validate whether your security/logging stack sees the callback pattern.
  4. Check the NetEm event timeline to confirm the callback reached the sink.

Availability stress

The Availability stress / DDoS impact action uses the built-in scenario engine to degrade quality progressively. It does not send a flood or attack traffic. This makes it suitable for testing how an SD-WAN design reacts to the operational symptoms of saturation without running a denial-of-service tool.

Bounded packet capture

Packet capture is an optional diagnostic wrapper around tcpdump. It is deliberately constrained:

GuardrailCurrent limit
InterfacesConfigured WAN inner or outer interfaces only
Concurrent capturesOne
Duration5–120 seconds
Packet count20,000 maximum
Snap length256 bytes per packet
Name resolutionDisabled (-nn)
Storageruntime/captures/

How to capture

  1. Select the target WAN.
  2. Select Inner for the firewall-facing side or Outer for the upstream-facing side.
  3. Select 15, 30, 60 or 120 seconds.
  4. Click Start capture.
  5. Reproduce the problem while the capture runs.
  6. Stop early if needed, then use Download last PCAP.

Requirements

tcpdump must be installed and the service needs packet-capture permission. In a systemd deployment, the service generally needs CAP_NET_RAW in addition to the existing CAP_NET_ADMIN.

AmbientCapabilities=CAP_NET_ADMIN CAP_NET_RAW
CapabilityBoundingSet=CAP_NET_ADMIN CAP_NET_RAW
tcpdump installed is not enough by itself: if capture starts failing with a permission error, verify the systemd capability set and restart the service after changing it.
