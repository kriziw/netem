Guided tests and conditional orchestration

The Tests page groups capabilities by validation outcome instead of implementation primitive. A test can now combine timed impairment stages with state-driven wait and assert stages.

Built-in tests

Progressive brownout, SLA failover, Flaky underlay and Availability stress remain available as one-click tests. The built-in SLA failover test now includes two assertions: expected SLA must fail after the blackhole and recover after the path is restored.

Supported scenario actions

ActionPurpose
qualityApply a 0–100% access-model quality level.
faultApply/clear bidirectional or one-way blackholes.
mtuApply 576–9000 byte MTU, or 0 to restore.
waitPause until a condition becomes true or the timeout expires.
assertEvaluate a condition as a pass/fail requirement; result is written to the Lab Session report.

Condition sources

  • Expected SLA: wait/assert on pass or fail for the scenario WAN or an explicitly named WAN.
  • Active probe: compare probe success or latency_ms using == != < <= > >=.
  • Measured traffic: compare persisted down_mbps, up_mbps, down_pps or up_pps.

Conditional stages support 1–600 second timeouts, 0.25–5 second polling, and on_fail behavior of stop or continue. A failed condition marks the overall scenario failed even when execution continues.

Conditional example

[
  {"after":0, "action":"quality", "value":100, "label":"Baseline"},
  {"after":10, "action":"fault", "value":"blackhole", "label":"Inject outage"},
  {"after":0, "action":"assert",
   "condition":{"type":"sla","state":"fail"},
   "timeout":5, "label":"Expected SLA detects failure"},
  {"after":20, "action":"fault", "value":"normal", "label":"Restore path"},
  {"after":0, "action":"wait",
   "condition":{"type":"sla","state":"pass"},
   "timeout":10, "label":"Wait for recovery"}
]

Probe assertion example

{"after":0, "action":"assert",
 "condition":{
   "type":"probe",
   "probe_id":"probe-wan1-internet",
   "field":"success",
   "op":"==",
   "value":false
 },
 "timeout":8,
 "label":"Internet probe fails"}

Probe conditions reject stale results instead of treating an old success/failure as current evidence.

Running-test state

The sticky running-test bar shows the current stage, condition description, latest observed value and true stage-count progress. Stop & restore interrupts both timed waits and conditional polling.

Assertions and Lab Sessions

Start a Lab Session before running a scored validation. Every assertion writes an assertion event containing the requirement, observed value, elapsed evaluation time and PASS/FAIL result. Completed session reports aggregate those results automatically.

Security and capture tools

EICAR, benign beacon and bounded packet capture remain on the same Tests page. These are diagnostics/detection-validation tools and are not used as unrestricted offensive functionality.
