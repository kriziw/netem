Why Tests replaces feature-centric pages

The Tests page groups capabilities by validation outcome instead of implementation primitive. The normal path is to choose a test, select the target WAN and run it. Detailed scenario JSON remains available under Advanced.

Each card shows approximate duration and stage count. Only one scenario can run at a time. Completion or manual stop restores the configured WAN baseline.

Security tests

The same page contains the harmless EICAR artifact and benign beacon endpoint. These are intentionally safe detection/visibility tools rather than malware or unrestricted offensive tooling.

Packet capture

Packet capture is available in the same workflow so you can diagnose a test without leaving the page. It is limited to configured WAN interfaces, one capture at a time, 5–120 seconds, 20,000 packets and 256-byte snap length.

Custom tests

Saved custom scenarios appear below the guided tests. The advanced builder accepts the same validated JSON stage model as before: quality, fault and mtu actions, up to 30 stages.

[
  {"after": 0,  "action": "quality", "value": 100, "label": "Baseline"},
  {"after": 10, "action": "quality", "value": 45,  "label": "Brownout"},
  {"after": 15, "action": "fault",   "value": "blackhole", "label": "Outage"},

]

Running-test bar

While a scenario is active, a sticky running-test bar remains visible with the current stage and a Stop & restore action. The stage indicator updates from the live state API rather than requiring a page refresh.

Using Tests with Sessions

For a meaningful validation run, start a Lab Session first, then run one or more tests. Scenario, fault, MTU, capture and security events written during that period are associated with the active session automatically.
