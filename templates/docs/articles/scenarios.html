Why use scenarios

Scenarios turn one-off impairment changes into repeatable lab experiments. A scenario is an ordered list of stages. Each stage waits for its after interval, performs one supported action, updates runtime state and writes events to the timeline.

Only one scenario can run at a time. When it ends—or when you request a stop—the configured WAN profile is restored.

Run a scenario

  1. Open Tests.
  2. Choose the target WAN from the scenario card.
  3. Click Run.
  4. Watch the active-scenario banner and Overview/Analytics.
  5. Let the scenario finish, or use Stop & restore WAN if you need to abort it.

The stage timeline on each card shows cumulative elapsed time and the action/value that will be applied.

Custom scenario builder

Custom scenarios are stored in config.json. The current builder accepts a validated JSON array of stages. A scenario may contain up to 30 stages; up to 20 custom scenarios are retained.

[
  {"after": 0,  "action": "quality", "value": 100, "label": "Nominal"},
  {"after": 10, "action": "quality", "value": 45,  "label": "Brownout"},
  {"after": 15, "action": "mtu",     "value": 1300,"label": "MTU constrained"},
  {"after": 15, "action": "fault",   "value": "blackhole", "label": "Outage"},
  {"after": 15, "action": "fault",   "value": "normal", "label": "Restore"},
  {"after": 5,  "action": "mtu",     "value": 0, "label": "MTU restored"}
]

Supported actions

ActionAccepted valueMeaning
quality0–100 integerApply the selected access profile at that quality level.
faultnormal, blackhole, downstream_blackhole, upstream_blackholeApply or clear a runtime data-plane fault.
phaseNamed phaseMark a measurement phase without changing impairment.
traffic_generatorstart, adjust, stop operation objectControl the simulator workload.
wait / assertCondition object, timeout, poll and on_failWait for a measured condition or record an assertion outcome.
mtu576–9000, or 0Apply a temporary path MTU; 0 restores the original value.

after must be an integer from 0 to 3600 seconds. Values outside supported ranges are rejected or bounded by validation. Labels are limited to 80 characters.

Stop and restoration behavior

Stopping a scenario sets a stop request; the scenario runner exits its sequence and restores the persisted WAN profile. MTU state is also restored by the scenario cleanup path. This keeps the configured baseline authoritative.

Scenario events

Scenario start, stages, completion, stop, faults and MTU changes are written to the persistent event log. Use the activity panel on Tests for the recent view or Analytics for the broader event timeline/export.

Available conditions and planned orchestration

Condition-based wait and assert stages already support expected SLA, active probes, traffic thresholds, application experience and measured steering. Conditional timeouts are 1-600 seconds, polling is 0.25-5 seconds, and on_fail selects stop or continue.

Parallel WAN actions, branching, capture triggers and appliance-reported SD-WAN events remain planned improvements.
