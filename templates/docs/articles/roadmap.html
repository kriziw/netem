Recommended next features

With measurement, persistence, assertions and reports available, the highest-value next step is to correlate NetEm with the appliance under test and expand orchestration.

1. Vendor adapter framework + Fortinet first

Define a normalized adapter contract for WAN-member health, observed latency/jitter/loss, SLA state and selected path. Implement Fortinet first so session reports can calculate real detection and failover timing in the current lab, then reuse the contract for other vendors.

2. Parallel multi-WAN scenarios

Allow a test to manipulate multiple WANs at once: primary outage while backup degrades, staggered recovery, dual brownout and bounded chaos profiles.

3. Bounded traffic generator

Add a guarded iperf3 workflow with allowlisted/configured targets, hard bandwidth/PPS/duration limits, constant/burst/microburst modes, emergency stop and Lab Session correlation.

4. Session comparison analytics

Compare two completed validation runs: assertion outcomes, fail/recovery timing, probe percentiles, throughput behavior and later vendor-observed response. This is especially useful for before/after tuning and vendor/config comparisons.

5. qdisc and updater self-verification

After applying shaping, compare requested state with the kernel qdisc state and surface partial failures. Before an in-app update, verify Git/service-user permissions, working-tree cleanliness, fast-forward eligibility and restart policy.

6. Remote probe agent

Add a lightweight probe agent that can run behind the appliance under test. This removes the current transparent-bridge limitation of host-routed probes and gives true appliance-side path measurements without adding L3 addresses to NetEm's WAN bridge ports.

7. Shared-lab platform features

  • authentication and scoped API tokens;
  • configuration/profile/session backup and restore;
  • dynamic WAN count beyond two links;
  • additional vendor adapters.

Resilience metrics unlocked by the next adapter phase

Once vendor-observed events exist beside injected and measured state, session reports can calculate detection time, failover convergence, service interruption, recovery convergence and discrepancies between expected, measured and appliance-observed SLA state.

Recommended next implementation: the Fortinet adapter framework is now the logical next milestone. The measurement/evidence foundation it depends on is already present.
