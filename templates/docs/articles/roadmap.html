This page separates features already in the application from improvements still planned. SQLite data storage is available now.

Available now

CapabilityStatusWhat you can use today
Persistent historyAvailableSQLite stores WAN, host and probe measurements across restarts, with seven-day rolling retention. Session reports and downloadable test records are also saved on disk.
Application traffic and experienceAvailableThe Traffic Simulator runs simulated users and continuous application checks through a configured path to the controlled target. Tests and the showroom display measured application outcomes.
Active measurementsAvailableICMP, TCP, HTTP/HTTPS and DNS probes with saved results and failure/recovery events.
Conditional tests and reportsAvailableTimed stages, condition-based waits, assertions, workload controls, named phases, saved session reports and per-test evidence downloads.
Appliance inventory and FortiGate monitoringAvailableSaved device inventory, FortiGate management health and licence observations, alerts and test-start checks. Other vendors can be inventoried and selected as traffic paths.
Verified paths and controlled targetAvailableWorkload route verification, source-bound path health checks and controlled-target application measurements.
Shaping diagnosticsAvailableInjected conditions beside kernel-reported shaping, queue/drop measurements and host health.
Component updatesAvailableOne check for NetEm, Traffic Simulator and controlled-target updates, with separate installs. NetEm checks for local changes and requires a fast-forward update.

Use Analytics & SLA for measurement history, Lab Sessions for saved reports, and Appliances for monitoring and path setup.

Planned improvements

The items below describe additional work, rather than features that need enabling. They are not release-date commitments.

Appliance-reported SD-WAN behaviour

Extend vendor integrations with the appliance's own WAN SLA measurements, selected paths and transition events. FortiGate health/licence monitoring already exists; detailed SD-WAN observations and additional monitoring adapters remain planned.

Parallel WAN actions and richer orchestration

Add simultaneous impairment of several WANs, branching and capture triggers. Sequential condition-based waits and pass/fail assertions are already available.

Session comparison and evidence management

Add side-by-side comparisons of completed sessions, configurable retention and a guided backup/restore workflow. Existing SQLite history, saved session reports and test-record downloads provide the evidence foundation.

Additional traffic and fault tools

Add a guarded iperf3 workflow and PCAP replay alongside the existing application simulator. Dedicated PMTUD-blackhole simulation also remains planned; temporary MTU changes and directional/bidirectional outages already exist.

Stronger shaping and update checks

Build on the current shaping readback and Git update checks with comprehensive requested-versus-installed validation and service-permission/restart-policy preflight.

Additional remote probe locations

Add independently deployed probe-only agents at other locations. Simulator-to-controlled-target checks already exist. NetEm host-routed probes still cannot prove that traffic crossed a particular transparent WAN.

Shared-lab access and scale

  • Operator sign-in, roles and scoped NetEm API access;
  • dynamic WAN setup beyond the current two-WAN setup form;
  • more vendor monitoring adapters and report attachments for packet captures.

What the next observation layer adds

Appliance-reported path changes would let reports compare injected conditions, measured application impact and the appliance's own failure-detection and recovery decisions. Current traffic/application measurements and inferred steering remain separate from those future vendor observations.
