Product direction

The next phase should focus less on adding more sliders and more on turning existing impairment controls into measurable, repeatable validation. The target workflow is:

See what is happening → choose the outcome to test → inject a controlled condition → observe the device response → retain evidence → compare results

Recommended next milestone: measured truth + evidence

1. Active measurement engine

Add ICMP, TCP-connect, HTTP/HTTPS and DNS probes per WAN. This fills the biggest current gap: NetEm knows what it injected, but latency/jitter/loss are not yet independently measured end-to-end.

2. Persistent telemetry

Store throughput/PPS, injected impairment, probe results, SLA state, faults and scenario stages in SQLite. Keep Prometheus optional for external monitoring.

3. Session reports

Extend Lab Sessions with baseline snapshots, tests run, captures, assertions and downloadable evidence. This should become the primary record of a validation exercise.

SD-WAN response correlation

Introduce a normalized vendor adapter model for member health, observed latency/jitter/loss, SLA state and selected path. Implement Fortinet first, then reuse the same contract for Cisco, Palo Alto, Juniper, VMware/VeloCloud and Versa.

Test orchestration

  • conditional waits such as “wait until vendor SLA fails”;
  • assert failover/recovery within a threshold;
  • parallel multi-WAN actions;
  • timeouts, branches and automatic pass/fail results;
  • higher-level test templates for common resilience cases.

Traffic generation and replay

Add a bounded iperf3 wrapper for constant/burst/microburst traffic and a sanitized tcpreplay workflow. Both should be restricted to configured/allowlisted lab targets and include hard rate/duration limits plus an emergency stop.

Analytics evolution

Persist session-aware time series, annotate charts with scenario/fault/vendor events, compare WANs and sessions, and calculate automatic resilience metrics such as detection time, failover convergence, interruption window and recovery convergence.

Platform quality

  • update preflight that checks Git/service-user write permissions before fetch/merge;
  • runtime qdisc self-verification after every apply;
  • authentication, scoped API tokens and audit trail for shared labs;
  • configuration/profile/session backup and restore;
  • eventual dynamic WAN count beyond the current two-link topology.

Most important: the next feature should not be another impairment primitive. The platform already has a strong impairment engine. The highest-value step is measuring and proving what happens because of those impairments.
